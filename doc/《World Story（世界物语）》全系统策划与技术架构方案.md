## 一、 项目开发步骤与迭代路线

本项目复杂度高，禁止采用“先拼大地图再加玩法”的传统线性思路。建议按照“关键技术刺探 (Tech Spike) ➔ 核心玩具 (Core Toy) ➔ 垂直切片 (Vertical Slice) ➔ 工业化内容生产 (Content Scale) ➔ 性能终调 (Polish)”的五步敏捷节奏推进。

```
[Phase 0: 技术预研与尖刺刺探 (4~6 周)]
  └── 验证 4 大技术死穴：GDExtension 面合并、Jolt 物理压测、微观力学算法、端侧 SLM 串行推理
			│ 通过
			▼
[Phase 1: 核心玩具与 MVP 原型 (8~10 周)]
  └── 打造可玩最小闭环：16³ 微观建模 + 假人实测挥打 + 三视角平滑控制器 + 单 Chunk 破坏
			│ 验证好玩
			▼
[Phase 2: 垂直切片 Vertical Slice (12~14 周)]
  └── 双势力小规模世界：无限地形流式加载 + 原始与近代据点 + GOAP 领地施工 + AI 装备审读
			│ 确立量产标准
			▼
[Phase 3: 工业化内容扩充与玩法铺展 (14~16 周)]
  └── 补齐东方/西方势力、反求工程全科技链、批量建造蓝图、VAT 军团编队、数值平衡
			│ 锁定功能
			▼
[Phase 4: 极限性能压测与发售打磨 (6~8 周)]
  └── Zero-Allocation 内存清理、Steam Deck / 中端独显 60 FPS 达标、新手引导与体验调优

```

### 1.1 Phase 0: 核心技术预研与尖刺刺探 (Tech Spike, 4\~6 周)

* **目标**：不写非核心的业务 UI 与叙事，专攻 4 个可能导致项目推倒重来的“技术死穴”。

* **实施任务**：

  1. **体素吞吐 Spike**：用 C++ GDExtension 跑通 Greedy Meshing，在 `WorkerThreadPool` 中并发烘焙 64 个 Chunk，确认无主线程停顿。

  2. **物理崩坏 Spike**：在 Godot-Jolt 中实例化 1000 个带碰撞体的体素方块刚体，验证快速休眠机制（Sleep Threshold）下的物理帧率能否维持 60 FPS。

  3. **端侧 AI Spike**：在 GDExtension 中集成 `llama.cpp`，加载 Qwen2.5-3B 4-bit 模型，测量在后台线程生成 60 Tokens 期间对渲染主线程造成的卡顿（目标：主线程丢帧 $\le 1$ 帧）。

  4. **力学算法验证**：在纯脚本环境下完成质心、绕轴惯量张量、刃口投影压强公式的代码推导，用单测验证其数学稳定性。

### 1.2 Phase 1: 核心玩具与 MVP 原型 (8\~10 周)

* **目标**：跑通“玩家自己捏一把武器去打怪”的最小乐趣闭环。

* **实施任务**：

  1. 搭建可交互的 $16 \times 16 \times 16$ 工作台，支持放置木头、生铁、花岗岩三种材质方块。

  2. 接入 V-HACD 自动凸分解管线，把建模成果一键生成为带手持挂点的 `RigidBody3D` 道具。

  3. 构建统一摄像机控制器（`CameraRig.gd`），实现 FP（第一人称）、TP（第三人称）、RTS（上帝视角）平滑过渡。

  4. 生成一个 $3 \times 3$ 的平地 Chunk 测试场，放置受击假人，测试不同重心/刃口武器的挥击手感、伤害差异与受力断裂。

### 1.3 Phase 2: 垂直切片 (Vertical Slice, 12\~14 周)

* **目标**：交付一个可对外演示、具备完整系统深度的“微型成品游戏”。

* **实施任务**：

  1. **世界系统**：落地 FastNoiseLite + Voronoi 双层生成，生成包含“原始丛林”与“近代城邦”两个势力的 $2\text{km} \times 2\text{km}$ 大地图。

  2. **AI-NPC 闭环**：

	 * NPC 视野捕捉玩家手持武器，向本地 SLM 发送结构化 Prompt，并在头顶弹出性格化吐槽台词气泡。

	 * 上帝视角下框选 NPC，下达建筑蓝图，NPC 通过 GOAP 规划自动搬运体素方块施工。

  3. **渲染规范确立**：落地 Bevel 着色器、SDFGI 全局光照与 RTS 移轴景深，确立美术基准。

### 1.4 Phase 3: 工业化内容扩充与玩法铺展 (14\~16 周)

* **目标**：横向铺开四大文明势力，充实科技树与游戏体量。

* **实施任务**：

  1. 补全古代东方（榫卯/连弩/黑火药）与古代西方（拱券/板甲/投石机）的建筑蓝图与构件库。

  2. 实现反求工程台（Reverse Engineering Table）物理逐层拆解与功能体素解锁逻辑。

  3. 实现 30m 外 NPC 的顶点动画贴图（VAT）切换，支持上帝视角百人同屏作战。

  4. 数值平衡：微调全部材料密度、莫氏硬度、抗拉韧性与攻速体力消耗曲线。

### 1.5 Phase 4: 极限性能压测与发售打磨 (6\~8 周)

* **目标**：消除顿挫，完成 Steam 集成与全平台体验封包。

* **实施任务**：

  1. 全局内存排查：消除 `_physics_process` 中的内存分配，完善抛射物与碎块对象池。

  2. AI 降频与熔断测试：在极低算力配置下测试 SLM 推理队列的超时熔断机制。

  3. 新手引导与 UX 重构：简化微观工作台的操作辅助线与吸附对齐功能。

## 三、 核心开发规则与工程铁律

为防止物理引擎穿模崩溃、内存频繁触发 GC 卡顿或大模型把主线程拖死，项目团队必须严格遵循以下**七条工程铁律**：

### 铁律 1：严禁在 `_physics_process` 中分配堆内存 (Zero-Allocation)

* **规程**：在帧循环中，禁止动态执行 `PhysicsRayQueryParameters3D.create(...)`、`Array.new()` 或任何字典实例化。

* **落地**：所有射线参数、AABB 碰撞盒必须定义在脚本顶层作为复用单例；循环只改变其属性，不重新 `new()`。

### 铁律 2：自制活动刚体严禁使用凹面网格 (No Concave Trimesh)

* **规程**：玩家自建的异形武器，绝对禁止以 `ConcavePolygonShape3D` 参与动态刚体碰撞计算。

* **落地**：必须且只能在完成拼装时，经由后台运行凸分解，输出为顶点数 $\le 32$ 的极简单一凸包或复合盒体（Compound BoxShape3D）。

### 铁律 3：体素密集计算严禁使用纯 GDScript 跑循环

* **规程**：涉及遍历 $16^3 = 4096$ 体素数组的面剔除、Greedy Meshing 合并、BFS 连通图最小割断裂计算，严禁用 GDScript 嵌套 `for` 循环。

* **落地**：逻辑统一下沉至 C++ GDExtension，通过多线程任务 `WorkerThreadPool` 派发执行。

### 铁律 4：端侧大模型实施全局单例排队与 Token 节流

* **规程**：禁止任何 NPC 直接拥有独立的模型实例；严禁在同 1 物理帧内发起 2 次及以上的模型前向推理。

* **落地**：

  * 必须通过单例 `LLMQueueManager` 排队，优先级：当前对话 NPC > 警戒对峙 NPC > 闲置 NPC。

  * Prompt 强制限制在 300 Tokens 内，输出锁定在 60 Tokens 内，且必须配置静态 JSON Grammar。

### 铁律 5：刚体碎片实施“双轨分流”与强制睡眠

* **规程**：建筑爆破或武器折断时，禁止无节制生成全功能物理刚体。

* **落地**：仅关键受力受损的 10% 骨架生成为 `RigidBody3D`，且位移速度 $< 0.05\text{m/s}$ 持续 $0.5\text{s}$ 必须立即 `set_freeze_enabled(true)`；其余 90% 碎屑一律移交 `GPUParticles3D` 纯 GPU 模拟。

### 铁律 6：GOAP 状态规划实施时分复用

* **规程**：领地内聚集 50+ 劳作单位时，禁止同一物理帧内全体运行 A\* 目标空间搜索。

* **落地**：每帧最多轮询 2 个单位进行规划更新，其余单位严格消费已缓存的 Action 步骤。

### 铁律 7：跨视角渲染实施资产降级

* **规程**：严禁在上帝视角（RTS 模式）下维持第一人称级别的高精渲染配置。

* **落地**：

  * 拉升至上帝视角时，动态将相机阴影距离收缩至 40m 内，SDFGI 级数从 8 级降为 4 级。

  * 超过 30m 视距的 NPC 强行关闭 `Skeleton3D` 骨骼解算，切换为 GPU 顶点动画贴图（VAT）。

## 四、 资产与代码规范

### 4.1 Git 版本控制与 LFS 资产管线

* **主干保护策略**：

  * `main`：受保护分支，仅允许已通过打包测试的 Milestone 版本合入。

  * `develop`：日常集成主分支，所有 PR 必须经过至少 1 名核心程序审查（Code Review）。

  * `feature/xxx`：个人功能分支，严禁向其提交无关杂项。

* **Git LFS 强行追踪资产类型**：
  以下文件必须加入 `.gitattributes` 由 LFS 托管，严禁进入常规 Git 索引：

  ```
  *.gguf filter=lfs diff=lfs merge=lfs -text    # 端侧大模型权重文件
  *.blend filter=lfs diff=lfs merge=lfs -text   # Blender 原始工程
  *.vox filter=lfs diff=lfs merge=lfs -text     # MagicaVoxel 原始工程
  *.exr filter=lfs diff=lfs merge=lfs -text     # HDR 环境贴图
  *.wav filter=lfs diff=lfs merge=lfs -text     # 无损物理碰撞音频
  
  ```

### 4.2 资产与脚本命名约定

* **脚本文件**：PascalCase，与类名保持一致（如 `PhysicsEvaluator.gd`、`GreedyMesher.cpp`）。

* **全局单例（Autoload）**：前缀加 `G` 或以 `Manager` 结尾（如 `EventBus.gd`、`GameManager.gd`）。

* **着色器文件**：`PascalCase.gdshader`，微观材质与地形材质严格分目录存放。

* **体素预制件（Schematics）**：`[势力前缀]_[建筑类型]_[等级].tres`（如 `Eastern_Watchtower_T2.tres`）。

## 五、 质量门禁与验收准则 (Definition of Done - DoD)

各阶段的代码与玩法只有在通过以下量化测试指标后，方可宣布“完成”并合入主线：

### 5.1 物理微观建模验收门禁

* \[ \] **数学防崩验证**：输入“单点悬挑方块”、“全空网格”、“单一体素”等极端边界案例时，求解器未发生除以零、`NaN` 坐标或浮点溢出。

* \[ \] **手感与阻尼测试**：武器质心无论如何外偏，角色攻击前摇最大封顶在 $1.2\text{s}$，耐力消耗最低不少于 $5$ 点，防止数值畸变出现“永动机刀”。

* \[ \] **凸分解耗时达标**：$32^3$ 网格烘焙凸包的总耗时在后台线程中低于 $200\text{ms}$，生成的碰撞体凸包顶点数 $\le 32$。

### 5.2 大世界流式体素验收门禁

* \[ \] **多线程加载无顿挫**：玩家以 $15\text{m/s}$ 高速穿行跨越 Chunk 边界时，主线程渲染帧耗时波动小于 $2.0\text{ms}$，无感知掉帧。

* \[ \] **内存上限控制**：加载半斤为 $8$ 个 Chunk 的活动视野时，体素常驻内存（不含模型显存）稳定小于 $40\text{MB}$。

### 5.3 性能红线基准（以主流游戏 PC：RTX 3060 / GTX 1660 为准）

* \[ \] **上帝视角压测**：高空俯瞰基地、同屏 200 个 NPC 处于劳作与防守状态时，稳定输出 **60 FPS**，1% Low 帧不低于 **45 FPS**。

* \[ \] **物理碎块激战压测**：5 门火炮同时轰塌一处中型石质建筑、生成 300+ 物理碎块与粒子时，物理引擎解算耗时（Physics Time）单帧低于 **8.0ms**（不发生丢物理 Tick）。

* \[ \] **端侧 AI 串行验证**：连续与 3 名守卫对话，本地大模型异步串行吐字首字延迟（TTFT）$\le 800\text{ms}$，且返回的 JSON 经由 Schema 校验 $100\%$ 合法，无语法反序列化报错。
